# 実利用フローの監査（2026-09-21）

## 設計と検証範囲

README・SPEC・domain・画面・SQLite境界・既存テストを確認した。正本はローカルSQLite。計画生成は独立した関数、設定変更は提案と承認、実績は計画とは別の加算記録。複数試験は同じ枠と月〜日の割当上限を共有する。所要時間でセッションを作り、休憩は日別の実時間帯に確保する。未報告は0問にしない。見た目の全面変更・同期・通知などの機能追加は行わない。

検証データは架空の学生を想定した `tests/fixtures/student.ts`。授業期間3週間とその後の休暇、朝昼夕の食事、往復50分ずつの通学、重複するアルバイト予定、終日の外出を登録。行政書士は137問・2周・3分/問、予備試験は37問・2周・30分/問と40分/問。初期完了数を含む。目標日・優先度・復習期間を別に持つ。通常データへテスト用の設定や実績を書き込まない。

## 発見・修正

1. **進捗記録で承認待ち条件が消える**。記録処理が古い計画案を無効化してから再計画するため、案に含む候補設定も見失っていた。記録前の候補を明示して、新しい実績から再計算する。訂正・取消も同様。候補の総問題数が新しい完了数を下回った場合は、実績を保存して承認可能な案を消し、候補を修正用の下書きに残す。設定変更を勝手に承認しない。
2. **固定枠と教材負荷の不整合**。空き枠に収まるかしか調べていなかったため、1問の所要時間を増やしても短い固定枠へ同じ問題数を残して承認できた。問題数×現行の推定時間が固定枠を超えると競合にし、日付・所要時間・枠の長さと修正先を表示する。固定の長さを勝手に増やしたり問題数を減らしたりしない。短くなった推定時間は固定枠内に収まるため許容する。
3. **固定による教材順序の逆転**。新規の割当だけで前後関係を判定していた。将来の固定予定について、先行教材・周回の残量をその開始前にすべて配置できるかも検査する。逆転時は順序の確認・固定解除へ案内し、承認時も再検証する。過去・当日開始済みの予定は修正しない。
4. **lintコマンドが未整備**。ESLintとtypescript-eslintの推奨ルールでソース・テストの検査を追加。未使用importを整理。日本語の表示用全角空白と書き出し用の制御文字除去は理由を示して許容する。型検査も独立したコマンドにした。導入は[公式ガイド](https://typescript-eslint.io/getting-started/)に基づく。

いずれも再現テストで不整合を確認してから修正。計画・実績・正常な保存データの一括書換えはない。

画面確認では、配分の複数段階で同じ教材・周回の45分枠が休憩なしで2枚に分かれる表示も発見した。同じ集中枠内の連続する新規学習予定を統合する。時間と問題数の合計は保ち、固定・過去・別教材・休憩をまたぐ統合は行わない。

## 変更しない事項と検証限界

- 計画は分散とまとまりを優先するヒューリスティックで、最適配置の保証はしない。不足は隠さず表示する。最適化ソルバーへの置換は今回行わない。
- 可処分枠は登録された学習枠を基準とする。未登録の睡眠・移動や実際の学習時間を推測しない。休憩枠は保守的に確保する既存仕様を維持する。
- レポートの全体進捗は出力時点、過去週の予定は現在保存された承認済み計画。過去時点の完全な集計復元や、負荷で重み付けした達成率へは変更しない。
- ICSの書出しと形式検査を行う。外部カレンダーへの取込・同期・相手側での重複処理は対象外。
- 自動検査はWindowsのTauri/WebView2。WindowsのDPI変更、複数モニター間の移動、スクリーンリーダーの手動操作、更新ダイアログの実操作は未検証。
- 現在のSQLite監査履歴は完全スナップショットを保存する。履歴を自動削除する保持期間は設けない。長年の運用でのDBサイズ増加は残る制約で、正常データを削る変更は行わない。

実行コマンド・件数・配布物の確認結果は `VALIDATION.md` に記録する。
