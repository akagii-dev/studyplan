# StudyPlan 実装仕様

## 目的と対象

複数資格試験の学習計画と教材の進捗を、この端末だけで管理する日本語デスクトップアプリ。Tauri 2 + React + TypeScript + SQLiteを使用する。自由会話の解釈は行わず、選択ボタンと入力フォームで操作する。

対象環境はWindows。LLM API、ChatGPTメモリ連携、クラウド同期、外部カレンダーとの同期・取込、通知、アカウント登録は実装しない。追加要望により、学習予定・大学の授業のICSファイル書き出しに対応する。ネット接続は開発依存パッケージの取得時のみ必要。アプリの通常利用に外部サービスは不要。

追加要望により、週間の実績と全体進捗を比較するMarkdownレポートの書き出しにも対応する。

プロジェクトの目標に「1日の可処分時間の可視化」を含める。登録した学習可能枠から授業・予定・食事を除いた時間を可処分時間とし、睡眠など未設定の時間を自由時間として扱わない。

## 画面と初期設定

一般的な操作説明はサイドバーの独立した「チュートリアル」にまとめる。初期設定、時間、計画、記録、再計画、保存の6項目を一つずつ表示し、順番に進めるほか任意の項目を直接選べる。各項目から該当画面へ移動できる。閲覧・画面遷移だけでは設定・入力途中・実績を変更しない。起動時に強制表示しない。

通常画面では質問・入力・操作・現在の条件を中心に表示する。一般的な説明の折り畳み欄は撤去し、入力値の範囲、適用期間、時刻ラベル、延期した項目の影響、衝突警告、初期化・復元の確認は必要な場所に残す。

初期設定は「試験・目標」「勉強できる時間」「連続時間と休憩」「教材」「余裕率」の5段階。**1画面につき主に1つの質問**を表示する。日付範囲や開始・終了時刻など、セットで答える項目だけ同じ画面に置く。

- 試験名 → 目標日 → 計画開始日 → 優先度 → 表示色 → 復習期間の有無 → 日数 → 確認。
- 学習枠の適用期間 → 曜日 → 時間帯 → 追加する枠の有無。
- 授業登録の有無 → 時間割の適用期間 → 時限開始時刻 → 月〜金の時間割でコマを選択。
- 授業以外の定期予定は、有無 → 名前 → 期間 → 曜日 → 時間帯。
- 単発予定は、有無 → 日付 → 終日または時間帯 → 確認。
- 朝食の開始時刻 → 長さ → 昼食の開始時刻 → 長さ → 夕食の開始時刻 → 長さ。各食事は30〜60分、毎日に適用する。
- 連続で勉強できる最長時間 → 休憩時間。
- 対象試験 → 教材名 → 総問題数 → 周回数 → **各周回の初期完了数を1周ずつ** → 推定時間 → 必要に応じて周回別時間 → 順序 → 確認。
- 余裕率 → 全体確認 → 計画案作成。

復習期間・授業・定期予定・単発予定は、選択ボタンで省略し、後から設定できる。「前の質問」で回答を修正できる。質問位置、戻り先、入力途中の値をSQLiteに保存する。複数試験・複数教材・複数時間枠は確認画面から追加できる。

授業・定期予定・単発予定は「予定がない」と「あとで設定する」を別の回答として保存する。「あとで設定する」の直前に、未登録の時間は空き枠から除かれず、授業・毎週の予定・勉強できない日にも学習が入る可能性を項目別に説明する。登録済みの予定は引き続き除外する。初期設定の最終確認、計画案、計画を作成した後のホームにも同じ注意を表示する。

延期した項目は、設定一覧の「予定の確認状況」で登録内容の確認を完了するか、「予定がないことを確認」するまで注意を残す。初期設定の登録フローを最後まで完了した場合も確認済みになる。確認状態はSQLiteの設定内に保存し、再起動しても残る。既存のデータで未回答かつ予定も未登録の項目は「未確認」とし、勝手に「予定なし」にしない。確認状況の変更では進捗・承認済み計画を変更せず、古い計画案だけ破棄する。予定の追加後は計画案を作り直して承認する。

任意の予定が未確認でも、注意を表示したまま計画は作成・承認できる。試験・教材・勉強できる時間枠そのものが未登録の場合は、計算できない理由と登録先を示すエラーにし、画面からの計画作成と承認を止める。

詳しい設定は、別途「試験・目標」「教材・進捗」「時間枠・時間割」「連続時間・余裕率」の一覧編集画面から変更する。設定の保存だけでは承認済み計画を書き換えず、新しい案の作成と承認を行う。

## 数値の入力と確定

問題数・所要時間・集中量・復習日数・余裕率などの任意数値欄は、編集中の文字列と確定値を分離する。全消去して空欄にでき、空欄を0へ変換しない。入力途中はSQLiteの`draft.numberEdits`へ保存する。Enterまたは送信・次へボタンを押したときに、空欄、数値形式、整数または小数の単位、上下限を検証して確定値へ反映する。日付・時刻は専用入力欄を使う。

質問画面ではEnter1回で入力を検証・確定し、そのまま次の質問へ進む。「次へ」のクリックでも編集中の数値を検証してから進む。二段階のEnter操作を求めない。空欄・型・範囲のエラーがあれば同じ質問に留まる。日本語変換中のEnterとキーの押しっぱなしによる連続送信は無視する。「入力を戻す」は編集中の文字列を破棄する。一覧編集ではEnterで数値を確定でき、保存ボタンでも確定する。

進捗の任意問題数は入力文字列を `draft.progress.custom` に保存し、有効な整数ならそのまま「記録する」を押せる。入力後のEnter1回でも検証して記録する。空欄を0へ変換せず、非整数・残数超過・指数表記を受け付けない。旧版の `draft.numberEdits` に残る入力途中の問題数も引き継ぎ、入力変更または登録時に新しい保存形式へ移す。

## 配色

サイドバーでミントグリーン・ペールブルー・ライムを選べる。選択はSQLiteに保存し、再起動後も復元する。テーマは計画条件から独立しており、テーマ変更で設定更新日時や計画を変更しない。試験ごとの表示色は維持する。ライムは[Misskeyの公式サイト](https://misskey-hub.net/ja/)の明るい緑を参考にした独自配色で、ロゴや素材は複製していない。

### 表示とキーボード操作

3テーマの補助文字、警告文、取消ボタンは淡い背景でも読める濃さにする。カレンダーの前後の月と取消済み履歴は全体を半透明にせず、背景・状態ラベルで区別する。学習予定の色分けは枠線・背景・凡例に使い、詳細の試験名は共通文字色で表示する。選択中の色見本も指定した色を表示する。

淡い背景と白いカードを保ち、本文・補助文字と区切り線の濃さを全テーマで強める。入力欄と操作ボタンはカードの区切りより濃い枠線を使い、入力ラベル・プレースホルダーも読みやすくする。現在ページは左のアクセント線、選択ボタンは内側の枠線、カレンダー表示切替は濃い背景で区別する。無効なボタンは全体を半透明にせず、控えめな背景・枠線と読める文字色で表す。

カレンダーの教材名・予定問題数・実績マークの文字を拡大する。主要な入力・ボタン・リンク・開閉見出し・フォーカス可能領域は、キーボード操作時にテーマの濃い枠線で現在位置を示す。日別問題数の表にはTabで入り、矢印・Endキーでスクロールでき、列見出しをスクロール中も表示する。サイドバーとカレンダー表示切替は選択状態、進捗バーは対象名を支援技術に伝える。

別の画面へ移るときは先頭を表示し、その画面の見出しへフォーカスを移す。長い設定画面のスクロール位置を次の画面へ引き継がず、Tabによる操作も移動先の内容から続けられる。自動保存や同じ画面内の入力変更では、入力中のフォーカスとスクロール位置を変更しない。

自動検査は[W3Cの文字コントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)を含むaxe-coreのWCAG A/AAルールを参照する。自動検査だけで全画面・全支援技術への適合を保証するものではない。検査した画面と残る手動確認は動作確認記録に記載する。

## 初期設定の再編集と初期化

授業名の入力欄は月曜〜日曜、同じ曜日では開始時刻順に並べる。複数曜日を持つ授業の曜日ラベルも月曜始まりに揃える。保存時は授業IDを使い、表示の並び替えで保存済み設定の順序や授業との対応を変更しない。初期設定と時間割の編集画面で共通に適用する。

初期設定の上部に「設定項目を選んで修正する」を置く。既存の試験・教材・学習枠・定期予定・特定日・時間割の適用期間を選ぶと、最新の登録値を読み込んで対応する質問から再開する。食事・連続時間・休憩・余裕率も直接選択できる。既存の時間割期間の修正は、その期間の授業を新しい期間へ引き継ぐ。授業名は空欄でもよく、入力した名前はカレンダーと今日の予定に表示する。

初期化は対象を選んだ後、警告・影響の説明と確認チェックを経て実行する。「質問の進行だけ」は質問位置・初期設定の数値下書きを消し、登録済み設定・計画・実績を残す。「設定・計画・記録」は現在の登録データを初期値へ戻すが、直前の状態をSQLiteの resetBackup に1世代保存する。復元は初期化後の入力を置き換える警告と確認を必要とし、再起動後も利用できる。監査履歴は消去しないため、完全削除の機能ではない。テーマは初期化でも保持する。初期化を続けて行うと復元対象は直前の1回に更新される。

## 保存

正本はTauriのアプリデータディレクトリにある`studyplan.sqlite3`。Windowsでは通常 `%APPDATA%\jp.local.studyplan\studyplan.sqlite3`。

SQLite内の構造:

| テーブル   | 内容                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ |
| state      | 現在の設定、教材、入力途中、記録、計画、承認前計画履歴、未承認案を含むJSONとリビジョン。単一行。 |
| operations | 保存要求の一意IDと確定リビジョン。再送時は二重処理しない。                                       |
| audit      | リビジョンごとの完全な保存内容と保存日時。訂正前データも残す。                                   |
| restore_point | ファイル復元の直前の全状態と保存日時。1世代、単一行。 |

JSONはSQLiteの`json_valid`制約を持つ。ファイルやブラウザーのlocalStorageを正本として使用しない。書き込みは`BEGIN IMMEDIATE`トランザクション、WAL、`synchronous=FULL`を使用。期待リビジョンを照合し、古い画面からの上書きを拒否する。Rust側でも教材・周回・整数の完了数・残数超過・記録ID重複を検証する。

保存先の作成・DB接続は起動処理中に実行せず、画面からの最初のコマンドで行う。起動時の読み込みは非同期コマンドとし、保存先エラー・DB破損などで接続できなくても案内画面を開く。「もう一度読み込む」で同じ保存先を再試行し、原因とパスは折り畳んだ「エラーの詳細」で確認できる。ブラウザーだけで開いた場合はデスクトップ版の起動を案内する。

失敗した接続は解放し、次の操作で開き直す。読み込み失敗を空の初期状態として扱わず、自動初期化・ファイル削除・バックアップの自動適用は行わない。JSONが読める空のDBと、読み込みが失敗したDBを区別する。物理的に壊れたDBを修復する機能はない。SQLiteの user_version は設定変更の前に検査し、0（新規）・1以外の版ではデータを変更せず拒否する。

入力変更はメモリー上で即時表示し、保存を直列化する。「保存中…」「保存済み」を画面上に表示。保存失敗時はエラーを表示し、保存済みの状態を読み直す。通常のウィンドウ終了要求で未完了の保存がある場合、操作を一時停止して全保存の完了を待つ。待機中の繰り返し終了要求でも保存を飛ばさない。待機中に保存に失敗した場合は終了を中止し、保存済み内容の確認・再入力を案内する。強制終了・電源断にはこの待機処理は適用できない。

初期完了数は登録時の基準値。記録画面から追加した数を含めない。全記録と基準値の合計が総問題数を超える教材変更は拒否する。

### 保存状態が不明な場合

保存要求が失敗したらSQLiteの現在の内容を読み直す。読み直しにも失敗した場合は「保存未確認」と表示し、確認画面で通常の入力・画面遷移を止める。状態が不明なまま新しい変更や復元を重ねず、通常のウィンドウ終了も止める。終了待機中に障害が発生した場合も同じ確認へ戻る。元データの初期化や、保存成功の推定はしない。

「保存済みの内容を読み直す」で再試行する。成功したらSQLiteの状態とリビジョンに合わせて画面を更新し、入力を再開する。失敗し続けても画面の入力を新たに書き込まない。要求の応答だけが失われ、実際には保存された場合は保存された内容を読み取る。保存されなかった変更は入力し直すよう案内する。バックアップ復元の要求が失敗した場合も保存状態を読み直す。

読み直せない状態から終了する場合は「保存を確認せずに終了」で未保存の変更が失われることを表示し、さらに「終了する」を選んだ場合のみ閉じる。「戻る」ではアプリを閉じない。強制終了・電源断を防ぐ仕組みではない。確認画面はエラー時だけ表示し、通常の自動保存操作は変えない。

## バックアップと復元

サイドバーの「バックアップ」で保存・復元を行う。保存は未完了のSQLite書き込みがない時に利用でき、ネイティブの保存先選択後、確定済みSQLiteデータを書き出す。拡張子は `.studyplan.json`。形式名 `StudyPlanBackup`、形式バージョン1、作成日時、アプリバージョン、現在のAppStateを持つJSONで、最大50MiB。暗号化はしない。保存先と同じディレクトリの一時ファイルへ書き込み・同期してから置き換える。

設定、教材、記録（0問・取消済みを含む）、計画、固定、計画履歴、未承認案、入力途中、初期化前の控え、配色を含む。SQLiteの内部監査履歴・保存要求ID・リビジョン・ファイル復元前の控えは含まない。入力途中の空欄は空欄のまま保持する。

読み込み時は形式・型・日付・上限・版を検証し、Rust側でも同じJSON Schemaと教材参照・完了数を検証する。破損・未対応版・残数超過では現在のデータを変えない。ファイル名・作成日時・試験/教材/記録/予定の件数と全体を置き換える警告を表示し、確認チェック後に復元できる。表示した時点・取消時点では保存内容を変更しない。

承認時は書き込み待ちを終えてから、現在の全状態を `restore_point` へ控え、読み込んだ全状態に同一トランザクションで置き換える。元の提案・下書きもそのまま復元する。古いリビジョンの上書きと二重要求を防ぐ。初めての起動で復元した場合も、初期状態へ戻せる控えを作る。

「前回の復元前に戻す」は進捗記録も含めた全体復元であり、再計画の「前の計画へ戻す」と範囲が異なる。控えは再起動後も残り、通常の編集で上書きしない。新たなファイル復元で控えを更新し、復元取消では現在と控えを入れ替える。初期化の控え `resetBackup` とは別に管理する。

型定義は `backupSchema.ts` のZodから生成した `backupSchema.json` をRustにも同梱する。`tests/backup.test.ts` で一致を確認し、変更時は環境変数 `UPDATE_BACKUP_SCHEMA=1` で同テストを実行して生成し直す。空の初期状態は `initialState.json` をフロントエンドとRustの復元控えで共有する。

## 学習可能量

日付・時間帯はローカルの暦日と日内の分数で扱う。曜日は日曜0〜土曜6。適用期間の開始日・終了日は両端を含む。時刻区間は開始を含み終了を含まない。

1. 有効な学習枠を結合し、重なった部分を一度だけ数える。
2. 有効な授業・定期予定・単発予定・食事を結合し、学習枠から差し引く。重複予定は二重に差し引かない。
3. 空き枠を時刻順に、集中ブロックと休憩に区切る。端に短いブロックができても利用できる。空き枠が切れた場合も直前のブロックから必要な休憩を取る。日付の境界でも、前日の最後の空き枠で勉強した場合に必要な休憩を当日冒頭に確保する（実際の配置によらず保守的に確保）。
4. 連続時間を上限に、休憩を挟んで次のブロックを配置する。1日の集中総量による上限は設けない。連続時間と休憩は各1〜1440分。休憩0分は最長連続時間を守れなくなるためエラーとする。
5. その学習可能量から余裕率を差し引き、分単位で切り下げた量を割当上限にする。

「①予定を除いた空き枠」「②連続学習の長さ・休憩後の学習可能量」「③余裕率を適用した割当可能量」を別に保持し、日別の内訳で表示する。週合計の表示は①空き枠と②学習可能量に絞り、週単位のバッファー・余裕率適用後の合計は表示しない。全体設定の余裕率と計算への適用は維持する。試験別フィルターでも容量は全試験共通。

授業は標準100分。初期時限は09:00、10:50、13:10、15:00、16:50。開始時刻と適用期間を変更できる。授業のコマ数から学習量を推測しない。

余裕率の選択肢は10%、20%、30%、その他（0〜99%）。20%は製品の初期設定であり、科学的な係数という説明はしない。

### 食事と1日の内訳

朝食・昼食・夕食は任意整数30〜60分。初回の質問には仮の時刻08:00・12:00・19:00と45分を表示し、質問への回答を保存する。空欄の時刻は下書きだけに保存し、設定を壊さない。深夜の食事は日付をまたいで除外する。旧データに食事が未登録なら勝手に追加せず、未設定の影響を警告する。「時間枠・時間割」で対話編集でき、再計画では独立した候補設定として承認時に反映する。

ホームおよびカレンダーとは分けた内訳欄に、24時間のバー・項目別の合計・時刻別一覧を表示する。食事、授業・予定・移動、計画割当可能量、余裕、休憩、学習対象外・未設定に分ける。重複は食事→予定→学習枠の順で1回だけ数え、合計24時間になる。空き時間＝学習可能量＋休憩、学習可能量＝割当可能量＋余裕。これは容量の表示であり、実際に割り当てた勉強時間とは異なる。

カレンダーの月・週・一覧・日の予定カードには**勉強と大学の授業だけ**を表示する。食事・その他の予定・移動は予定カードに出さず、空き枠の計算と重複検出に使う。

旧保存データの focus（日次総量）は読み取り互換性のため残せるが、新計画では使わない。既存の block を最長連続時間として引き継ぐ。新計画には計算方式の版4を保存する。旧計画は書き換えず要再計画と表示し、旧方式の未承認案は承認できない。計画履歴や完了実績を移行で書き換えない。

## 計画アルゴリズム

純粋な計算処理は`src/domain/planner.ts`に分離。UI・Tauri・SQLiteを直接参照せずテストできる。

教材の各周回について `残数 = 総問題数 − 初期完了数 − 有効な追加記録の合計`、`必要分数 = 残数 × その周回の1問あたり推定分数` を計算して合算する。追加周回に自動的な速度向上は適用しない。

目標日は学習割当の対象外。通常教材は目標日の前日まで、復習期間がある場合はその期間の前日までに割り当てる。試験の計画開始日より前には割り当てない。新規計画も過去には作らず、開始日と当日の遅い方を使う。

全試験で**一つの枠集合**を共有し、割り当てるたびに枠を消費する。日ごとの配分目安は、残り必要量とその試験で使える残り容量に対する当日の割合から算出する。長い空き枠の日は多く、短い日は少なく割り当てる。残り必要量/残り容量による逼迫度、優先度、期限で候補を選ぶ。同じ試験では教材の順序を守り、その教材の周回を順に完了させる。同じ順序の教材は安定したID順で処理する。

問題数は整数のまま保持し、残数を5の倍数へ切り捨てたり切り上げたりしない。通常の割り当ては問題数ではなく、推定所要時間のまとまりを優先する。1問は1ブロックに収めるため、推定時間がブロックより長ければ未配置になる。秒に相当する小数分も内部計算可能だが、時刻表示は分単位。

復習は通常教材と別の「まとめの復習」枠で表示し、目標日前の指定期間内に共有枠を消費する。復習期間中の試験には、その日に学習対象となる試験数で分けた容量を通常教材の配置前に確保する。残り枠にも復習を置ける。復習には通常教材の問題数を付けない。復習期間に枠を全く確保できない場合は競合を表示する。

必要量が入らなければ、教材・周回ごとの未配置問題数、必要分数、理由を保持・表示する。連続学習の長さや余裕率を変更して帳尻を合わせない。未配置を明示したまま、置けた課題だけの案を承認することはできる。

### まとまったセッションの割り当て

問題数による共通の下限・5問刻みの丸めを設けない。教材の各周回の `Round.minutes` が「1単位（1問）あたりの推定所要時間」に相当する。予定時間は問題数×その周回の推定分数。60分の枠には短答3分なら最大20問、論文30分なら最大2問を置ける。論文1〜4問も時間が下限以上なら通常のセッションである。

`Settings.minimumSessionMinutes` は通常セッションの下限、`preferredSessionMinutes` は可能な限りまとめる時間の目安。初期値はそれぞれ10分・30分。旧設定で未指定なら同じ初期値として解釈し、保存済みデータ自体を自動で書き換えない。下限は1分以上、目安は下限以上・1440分以下の整数。「連続時間・余裕率」の「予定のまとまりを調整する」、または対話式再計画の同分野で変更できる。目安は厳密な上限ではなく、連続上限・共有枠・休憩・余裕率が優先される。

各枠の最大問題数は `floor(利用可能分数 / 1問あたり推定分数)`。日次配分と目安時間から整数の問題数を決め、下限に満たない通常セッションは次の枠へ繰り越す。最後の残数を同じ枠に含められる場合はまとめる。全期間の通常配置と残りの十分な枠への配置を先に行い、それでも残る課題に限って短い例外を認める。

下限未満の残数は、同じ教材・周回の前後の予定との統合を試す。前の枠に延長できなければ次の予定がある十分な枠にまとめる場合もある。共有枠、教材・周回の順序、開始時刻を守り、固定・経過済みの予定を統合や移動の対象にしない。統合済みの予定を再度削除しない。課題の消失、予定の重複、集中上限の超過は許可しない。

統合できない下限未満の予定には「教材・周回の完了」または「期限上必要」の理由を付ける。問題数だけでは理由を付けず、下限以上の予定には短時間の警告を表示しない。旧計画に問題数による例外理由が残っていても、十分な長さなら短時間の警告は表示しない。見直し時間を加えて下限まで水増ししない。進捗入力の5問刻みのボタンは独立した仕様として維持する。

別枠の復習にも通常の時間下限を使う。未配置は不足として残し、連続時間・休憩・余裕率を勝手に変更しない。計算方式が版4より古い案は承認できず、「時間を基準に案を更新する」から候補設定と固定予定を保持して作り直せる。既存計画や実績は、新しい案の承認まではそのまま維持する。

計算は分散とまとまりを優先するヒューリスティックであり、数学的な最適化ソルバーではない。ブロックの端数、教材順序などによって、理論上別の並べ方で入る課題を未配置にする可能性がある。計画対象は最大3660日。計画の妥当性と残数の保存を優先する。

## 時間割と設定の確認

「勉強できる開始時刻・終了時刻」は、学習予定を入れてよい最も早い時刻・最も遅い時刻として説明する。この範囲を全て勉強する指定ではない。授業・予定の時刻には「学習不可」と明記する。

授業前後の移動・準備時間を0〜180分の整数で設定可能。既存設定で未指定の場合は0分とし、勝手に余裕時間を追加しない。各授業の前と後から同じ分数を除外し、隣接する授業や予定との重複は結合する。日付をまたぐ除外にも対応する。学習ブロック間の休憩、余裕率とは別の設定であり、時間割のプレビューと計画に共通で適用する。

初期設定・詳細設定の時間割で選択したコマは、青灰色で「授業・学習不可」と表示する。空いているセルを学習可能枠とみなさない。時間割の直下で日付を選び、登録した学習枠、除外する授業・予定、除外後の学習枠と合計時間を確認できる。計画と同じ区間計算を使用し、適用期間・曜日・重複除外を一致させる。詳細設定の時限の変更は、選択中の適用期間の授業にだけ反映する。

計画には作成日時、計算条件の最終更新日時、計算に使用した設定の写し、当日の割当開始時刻を保存する。既存の計画にこれらがない場合は「記録なし」と表示し、現在の設定を当時の設定とみなさない。ホームとカレンダーの週間容量は現在の設定から算出し、その旨を表示する。保存済み計画と現在の設定が異なる場合はホーム・カレンダー・再計画で注意を表示し、新しい案を承認するまで旧計画を自動変更しない。授業・予定との衝突は予定詳細にも表示する。

## 計画設計時の表示

計画案と保存済み計画で、使用した連続時間・休憩・余裕率・適用期間・日時、一日ごとの予定問題数（全試験合計と試験別）を確認できる。予定0問は実績0問を意味しない。

計画案では「バッファーなし」を**余裕率0%で前から詰めて割り当てる参考計算**として表示する。現在の残数、授業・予定・適用期間、連続学習の長さ、休憩、共有枠、教材順序、復習期間、固定予定を維持する。試験ごとに通常教材の終了予定日と0%の参考終了日を並べる。不足や競合がある場合は終了日を断定せず、その状態を表示する。別枠の復習を教材終了日に含めない。比較では設定・承認済み計画・実績を変更しない。通常計画は引き続き分散配分し、参考日が数学的な最短日であることは保証しない。

計画案の作成後に計算条件が変わった場合は古い案を承認できない。現在の授業・予定に重なる将来の予定の承認も拒否する。

## カレンダー

月・週の枠内、日別詳細、一覧に大学の授業と勉強だけを表示する。日別詳細と一覧は授業・学習を開始時刻順に並べ、授業を「学習実績」の中に混在させない。学習の時刻は「学習予定」と表示し、問題数と推定時間から決まった配置時刻であって、実際に取り組んだ時刻の記録ではないと説明する。

保存済み学習予定は現在の授業・予定・移動準備と照合する。将来の衝突件数、枠内の警告、日別詳細で衝突する予定名と時刻を表示し、再計画へ案内する。終了と開始が同時刻の場合だけでは時間重複としない（区間は開始を含み終了を含まない）。衝突した保存済み計画を黙って移動・削除せず、承認された変更案で更新する。固定予定が衝突する場合は承認を止め、固定解除または条件変更を求める。

サイドバーに独立した「今日のスケジュール」を設ける。当日の勉強と大学の授業を時刻順に並べ、予定問題数・時刻・授業名・実績・固定状態を確認できる。ここから当日の進捗記録へ移動できる。表示は統合計画から抽出し、独立した再計算はしない。日付は表示中にも1分ごとに再評価する。

承認済みの統合計画を、全試験/試験別、月/週/一覧で切り替える。フィルターは計算結果を作り直さない。試験色、教材名、周回、予定問題数、時刻、未報告/報告済み、当日実績を確認できる。月表示は日付を選ぶと詳細と当日の記録を表示する。一覧・月詳細から予定を固定/解除できる。

実績は日付・教材・周回で集計する。複数ブロックにまたがる日の実績は「当日実績/当日予定」と明記し、各ブロックへ勝手に割り当てない。予定のない日の記録も当日の記録欄に残る。

月・週・一覧で選択日を共通に持ち、日別詳細・可処分時間・週間内訳を同じ選択日に合わせる。月の移動では可能なら同じ日を保ち、翌月にその日がなければ月末を選ぶ。週の移動では曜日を維持する。一覧でも予定のない日の実績（0問を含む）を表示し、試験フィルターと取消状態を反映する。授業だけの期間に「予定なし」を表示しない。未来の学習予定からの記録ボタンは「記録は当日から」と表示して無効化する。

## ICSファイルの書き出し

学習カレンダーの「ICSを書き出す」で開始日・終了日、学習予定、大学の授業を選ぶ。学習予定は全試験または特定試験を選べる。対象は承認済み統合計画の学習・復習セッションと、現在の時間割の適用期間・曜日に該当する授業。未承認案・食事・移動・一般の予定・通知は出力しない。授業名は入力済みの名前、未入力なら「大学の授業」を使用する。出力や保存先選択の取消でSQLiteの状態を変更しない。

[RFC 5545](https://www.rfc-editor.org/info/rfc5545/)に従うUTF-8の`.ics`を出力する。各日付の時刻を端末のタイムゾーンで解釈し、UTCのDTSTART/DTENDに変換する。日本語・改行・区切り記号をエスケープし、75バイト単位でUTF-8の文字境界を守って折り返す。24:00は翌日の00:00。秒より短い精度は秒単位へ丸め、開始と終了が同じ秒になる予定は出力エラーにする。UIDはセッションIDまたは授業IDと日付から安定して生成する。期間は最大3661日（開始日を含む）、件数は最大50,000件。保存先はネイティブダイアログで選び、一時ファイルを同じフォルダーに作成してから原子的に置き換える。

ファイルは書き出した時点の写しで、自動更新・削除同期は行わない。再取込時の重複処理は取込先に依存する。予定がない、種類が未選択、日付・時刻が不正な場合は保存前に知らせる。旧計画と現在の設定が異なる場合は注意を表示する。

## 進捗記録

1. 日付・教材・周回を選ぶ。記録日は当日以前。
2. 今回追加した問題数を`0/5/10/15/20/その他/残りすべて`から選ぶ。
3. 「記録する」で確定する。

その他を選んだときだけ整数入力欄を表示。非負の1問単位。残数を超えるボタンは無効。残りすべてはその時点の残数を追加する。記録ID、日付、教材、周回、追加問題数、作成/更新日時、取消状態を保存する。

0問は有効な報告で、既存の完了数を消さない。有効な記録が一つもない状態が未報告。未報告を自動で0問に変換しない。UIの送信ロック、安定した記録ID、保存操作ID、SQLiteのトランザクションとリビジョンで二重加算を防ぐ。

履歴から問題数を訂正、または確認後に取消できる。訂正/取消後は全有効記録から累計を再計算する。取消済みの行は履歴に残る。自由文、問題番号、実測時間は入力必須にせず、完了数から問題番号を推測しない。

## 再計画

再計画画面の上部に承認・破棄ボタンを置く。承認ボタンと同じカードに、承認を止めている理由と対応ボタンを表示する。未配置の課題がある場合は、承認する計画に含まれない問題数も近くに表示する。設定変更による古い案、必須設定の不足、予定の競合、未報告の扱いの未確認を、実際の無効化条件と同じ条件で表示する。競合・未報告は該当見出しへスクロールしてフォーカスを移し、未報告の扱いを確認した後は承認操作へ戻れる。確認への移動だけで承認・固定解除・0問の記録は行わない。

固定予定の時刻が使えない場合は、具体的な日付・開始終了時刻と原因を表示する。原因は授業・定期予定・単発予定・食事・移動との重複、学習可能枠の外、連続時間の上限、休憩枠、余裕率により残す時間に分ける。重複相手の名称と時間、または該当する設定値を示す。「条件を修正」で該当する対話の質問を開き、有効な編集中の下書き、なければ承認待ち案の条件を引き継ぐ。一般の計画エラーでは条件選択画面を開く。

将来の固定予定の時刻エラーには「固定を解除して案を更新」も用意する。この明示操作では対象の固定フラグだけを解除し、候補条件・進捗を保って案を再作成する。元の予定時刻と他の固定予定は動かさず、時刻の変更は承認後に適用する。「今の時刻で案を更新」では候補条件と固定を保ち、経過した予定を再評価する。

当日の開始済み予定（固定・未固定を含む）は過去の計画として残す。現在の枠に収まらないことや開始済み同士の重複で再計画の承認を止めない。新しい実績や0問を作ることはなく、未報告の確認は維持する。将来の固定との重複は引き続きエラーにする。旧版の「17.45時」のような小数時刻のエラーはHH:MMで案内し、案の更新で新しい判定へ切り替える。

「対話で条件を見直す」で現在の設定全体の独立した下書きを作成し、変更する分野と既存の項目を選択する。試験・目標日・優先度・復習日数・表示色、教材名・総問題数・周回数・周回ごとの推定時間・順序、学習可能枠・授業・定期予定・特定日の予定、連続時間・休憩・食事・授業前後・余裕率を一問ずつ修正できる。時間枠と予定は追加・削除も可能。登録済みの値を各入力欄へあらかじめ表示し、変更しない項目を維持する。

質問位置・回答は`draft.revision`に保存し、途中で閉じたり再起動したりしても再開できる。数値はEnter1回で検証と次の質問への移動を行う。下書き・案の作成中は元の設定と計画を変更しない。変更内容を確認して案を作成し、承認時に候補設定と計画を同じSQLite保存操作で更新する。案の破棄では現在の設定・計画を保持し、下書きから再作成できる。下書きそのものの破棄にも対応する。

編集中に別画面で元の設定や予定確認状態が変わった場合、古い下書きの適用を止める。承認時にも作成元設定と計画IDを検査する。進捗を記録して残数が変わった場合は、承認待ちの候補条件を引き継いで案を再計算する。再計画から初期完了数や実績を変更することはできず、総問題数を完了数より少なくする変更も拒否する。周回数は未着手の末尾から減らせる。ただし初期完了数、進捗記録（0問・取消済みも含む）、開始済み予定、固定予定が参照する周回は残す。案の段階では現在の周回数と計画を変えず、承認時に更新する。

「設定を変えずに再計画」も用意し、対話が不要な場合は現在の設定で案を作れる。計画を戻す操作は従来どおり計画のみを復元し、設定や進捗を巻き戻さない。

記録・訂正・取消後に残数から新しい案を作る。計画の作成に失敗しても記録は保存し、設定を直してから再計画できる。設定変更や固定変更で古い提案は破棄する。

- 過去の日と当日の開始済み予定を保持する。新規の割当は当日の現在時刻以降。
- 将来の固定予定はそのまま保持し、固定した問題数は残数の将来割当から差し引く。
- 固定予定が新しい設定で枠外/重複/残数超過となった場合は競合を表示し、承認を止める。ユーザーが固定を解除するか設定を直す。
- 過去および当日の開始済み予定の未報告は確認対象として一覧表示する。
- 実際には進めた未報告は、先に記録する。「未報告は記録を保留したまま、現在の残数を再配置する」を明示的にチェックするまで承認できない。
- 変更理由、日付・教材・周回別の承認前/提案問題数、提案の時刻・固定・復習枠、未配置量を表示する。
- 承認まで元の計画は不変。承認時は元の計画を履歴へ保存する。
- 「前の計画へ戻す」は計画だけを復元し、進捗記録や設定を巻き戻さない。復元した計画は現在の設定・残数と一致しないことがあるため、必要に応じて再計画する。

## 週間レポート

サイドバーの「週間レポート」で対象日（今日以前）を選ぶと、その日を含む月曜〜日曜を表示する。前の週・次の週・今週へ移動できる。週間の追加完了数、週間の予定、全体の完了数・総問題数・進捗率・残数、この週の追加完了数が全体の総問題数に占める割合を比較し、試験別・日別の表を表示する。「Markdownを保存」で `.md` ファイルを書き出す。教材・周回別の表と未報告対象もMarkdownに含む。

- 週の実績は記録対象日で集計する。作成・訂正日時ではない。現在有効な訂正結果を使い、取消済み記録と出力日より未来の記録を除く。3問・7問等を丸めない。
- 全体の総数は現在の教材の「総問題数×周回数」の合計。完了数は初期設定の完了数と出力日までの有効な記録を含む。過去週を選んだ場合も全体進捗は出力時点であり、週末時点の履歴を復元した値ではない。日付のない初期完了数を特定の週の実績に振り分けない。
- 予定問題数は出力時点の承認済み統合計画の学習セッションを使う。未承認案と問題数のない別枠の復習は含めない。教材の複数セッションの実績を重複加算しない。現在の設定と古い計画が一致しない場合は注意を表示する。
- 週間予定に対する記録割合は問題数の単純比較で、教材別の予定の達成を保証せず、100%超もそのまま表示する。分母0では割合を算出しない。教材間の難しさ・推定時間の差は重み付けしない。実測学習時間を推定して出力しない。
- 日付・教材・周回ごとに報告を判定し、0問の報告と未報告を区別する。開始時刻を過ぎた予定だけを未報告一覧へ載せ、未来の予定は「これから」とする。記録がない日の実績は「記録なし」とし、自動で0問の実績に変えない。
- ファイルには対象週、出力日時、承認済み計画の作成日時、集計定義を記載する。入力文字の改行・パイプ・Markdown記号・HTMLをエスケープして表を保護する。
- 出力時は保存待ちを確認してSQLiteから確定済み状態を読み直し、一つの写しで集計する。保存先の取消ではファイルを作らず、出力・閲覧で計画や実績を変更しない。保存はUTF-8、一時ファイルを同期してから原子的に置き換える。拡張子・内容・20MiB上限を検証し、失敗時は既存ファイルを保つ。
- 自動配信・外部サービスへの送信は行わない。選択した週の保存は都度の操作で行う。

## 制約と保守

- 計画と実績は別。予定だけで完了としない。
- 計画枠の固定はできるが、ドラッグによる手動時刻編集は今回の範囲外。
- 試験・教材の削除は記録との参照整合性を保つため用意していない。編集・追加は可能。
- アプリのバックアップは現在の状態を対象とし、全監査履歴を保存するDBファイルの完全コピーではない。
- 履歴と監査記録は自動削除しない。長期利用でサイズが増える。
- SQLiteスキーマはuser_version=1。restore_pointはCREATE TABLE IF NOT EXISTSで既存DBへ追加する。既存テーブルの互換性を壊す変更には移行処理が必要。
- 配布物は署名なしの実行ファイル。インストーラーと自動更新は含まない。WebView2 Runtimeが必要。

Tauriのコマンド境界は公式資料に準拠: [Calling Rust from the Frontend](https://v2.tauri.app/develop/calling-rust/)、[Configuration](https://v2.tauri.app/reference/config/)。


## v0.2.0：試験・教材の追加と計画への反映

ホームと各一覧の「試験を追加」「教材を追加」で、初期設定と同じ一問ずつの質問を、その項目だけに絞って表示する。試験の登録後は対象試験を選択済みにして教材の質問へ進める。教材の入力途中がすでにあれば「入力途中の教材の追加を再開」と表示し、その回答を優先して保持する。既存項目の編集は一覧の編集ボタンで行う。

追加の回答・質問位置・戻り先は `draft.addExam` / `draft.addMaterial` に別々に保存し、初期設定の下書きや他の設定を変更しない。「中断して一覧へ」の後や再起動後は一覧の再開ボタンで続けられる。数値の空欄も保持し、Enter1回で検証と次へ進む。登録前は実際の試験・教材一覧に追加しない。

最終確認の「試験を登録する」「教材を登録する」で設定へ保存する。同じIDと送信中のガードで二重追加を防ぐ。既存計画・実績・固定は維持し、旧条件の未承認案は破棄する。その影響は登録直前にも表示する。新しい周回に速くなる仮定は入れず、問題数は1問単位で扱う。

登録後と一覧に「登録済み・計画への反映待ち」と、計画案の確認ボタンを表示する。試験・教材・学習枠が不足すれば、必要な入力へ移動するボタンを表示する。案がすでにあればその確認へ進む。計画にまだ含まれていない試験・教材は一覧で「計画に未反映」と表示する。

計画案には前の計画から追加された試験・教材名などの設定差を表示する。承認後にカレンダーが更新されること、案の破棄では登録した試験・教材が消えないことを案内する。承認／破棄の完了メッセージとカレンダーへ進むボタンを表示し、完了見出しへフォーカスを移す。承認・破棄も処理中は重複実行を防ぐ。既存の競合・未報告確認・元計画の保管は維持する。

## 更新パッケージ

アプリの版は画面下部・Tauri・Cargo・package.jsonで0.2.5に統一する。`scripts/package-update.ps1`で実行ファイル、SHA-256と版のmanifest、`Update.cmd`、PowerShell更新処理、手順書をZIPへまとめる。通信や自動更新は追加しない。差分バイナリではなく、実行ファイル全体の差し替えパッケージとする。

ユーザーが更新対象の既存exeを選択する。更新用exeのハッシュ・版、対象の製品名・版・起動状態を確認し、対象と同じフォルダーに検証済みの一時ファイルを作って原子的に置換する。旧exeは一意の名前で同じ場所に残す。起動中やロック・破損などで失敗すれば更新を止める。同一ハッシュの再実行は更新済みとして終了する。別アプリや新しい版への上書きは拒否する。

SQLiteの保存先・スキーマは変更せず、更新処理から設定・計画・記録へ書き込まない。0.1.0の既存データをそのまま読み込める。旧exeへの差し戻しは実行ファイルの差し替えのみで、進捗の巻き戻しではない。PowerShellが制限された環境では手動でexeを差し替えられる。


## 学習枠の未登録期間と長期計画の確認（v0.2.2）

試験の計画開始日または今日の遅い方から目標日前日まで、学習可能枠の適用期間に空白がないか確認する。期間は全試験で共有し、重複・包含・隣接を結合する。選択していない曜日は週ごとの休みなので未登録とはしない。授業・定期予定を登録しても学習可能枠の適用期間は延長しない。別枠の復習期間も確認対象とする。

未登録期間は、従来どおり割当可能時間が0になる。このため、たとえば目標が6月でも学習枠が2月までなら、全課題を2月までの枠へ配置する計算になる。未登録を学習不能と区別せず黙って早い終了日だけを提示したことが、今回の設計上の問題。時間枠を自動延長せず、初期設定の確認、ホーム、カレンダー、再計画に対象試験・未登録期間・登録済み期間に学習が集中する影響を表示する。意図した休みもあるため警告とし、承認を一律には禁止しない。

残りの計画期間が90日以上で学習枠の未登録期間がある場合、長期計画として「登録済みの枠だけで全周回を配置するため、学習枠・周回数・目標日を見直す」警告を加える。90日は製品上の案内基準であり、計算容量や期日を変更する係数ではない。期間がすべて登録済みなら、長期という理由だけで警告しない。

再計画の警告には「この期間の学習枠を追加」「周回数を見直す」「目標日を見直す」を置く。追加の期間は未登録の範囲を初期値にし、直前の学習枠がある場合だけ曜日・時刻を下書きへ引き継ぐ。名称・期間・曜日・開始・終了を一問ずつ確認・修正する。春休みの実際の期間や授業の有無を推測しない。既存の授業期間・承認済み計画・実績は維持し、承認時だけ設定と計画を反映する。別の修正途中の下書きや承認待ちの候補設定も引き継ぐ。同じ未登録期間を再度選んでも下書きの時間枠を重複追加しない。

週間Markdownには、承認済み計画の設定を用いて、出力日以降の未登録期間と長期計画の見直し警告を出す。現在の未承認設定で過去の計画に対する警告を消さない。計画の設定スナップショットがない旧データは期間の推定をしない。

## 進捗円グラフと表示設定（v0.2.5）

進捗記録画面の装飾メッセージと本のイラストを、完了・残りを示すドーナツ型の円グラフへ置き換える。初期表示は「全教材・全周回」で、「選択中の周回」へ切り替えられる。初期完了数と取消されていない記録を既存のcompleted関数で合算し、問題数ベースの割合・完了数・残数を表示する。未確定の入力は加算せず、保存した記録・訂正・取消を反映する。教材がない場合はグラフを表示せず案内する。0%・100%を扱い、900px幅でもグラフを隠さない。周回の切替状態は画面内だけに持つ。

試験色の候補を5色から16色へ増やし、対話式の初期設定・追加・再編集と一覧の編集で共通の候補を使用する。従来の5色・任意色・既存の試験色は維持する。

サイドバーの「表示モード」でライト・ダーク・システムを選択する。既存の3配色（ミントグリーン・ペールブルー・ライム）とは独立し、システム選択時はOSのprefers-color-schemeの変更にも追従する。CSSのcolor-schemeとHTMLのtheme-colorも実際の表示に合わせる。背景・文字・操作部品・授業枠・警告・エラー・円グラフに明暗別の色を適用する。

表示モードはSQLiteの状態にappearanceとして保存し、再起動・バックアップ・復元に引き継ぐ。旧データで未指定なら従来どおりライトとする。全初期化でも配色と表示モードは保持する。SQLiteの保存先・計画や実績の計算方法は変更しない。
