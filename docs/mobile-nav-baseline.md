アイコンと文字は各ペア内では同じ x だが、**どちらも4分割領域の中心にない**。文字の `text-align:center` は文字要素の内側にしか効いていない。基底 `nav button` の `justify-content:flex-start` とスマホ用 `display:grid; place-items:center` が併存し、グリッドの列がボタン左側へ寄っている（`src/style.css:548`, `:2832`）。[320px の今日](ux-after-eval/mobile-nav-320-today.png) と [390px の設定](ux-after-eval/mobile-nav-390-settings.png) で左寄りを確認できる。

4項目「今日」「今後の予定」「記録履歴」「設定」を各幅で順にタップした。すべて該当画面に遷移し、`aria-current="page"` と見出しが一致した。ボタンの縦タップ領域は48.14px、幅は320px時78px、375px時91.75px、390px時95.5px。選択状態は背景色と上側の線で見える。どの幅でも `document.documentElement.scrollWidth` は viewport 幅と同じで、横はみ出しなし。

**安全領域は未検証。** Edgeのモバイルエミュレーションでは下端の安全領域が0で、ホームインジケーターのある実機は操作できていない。コード上の下部ナビは `bottom:0`、`padding:4px` で `env(safe-area-inset-bottom)` を使っていない（`src/style.css:2829`）。そのため実機でラベルやタップ領域がシステム領域と重なる可能性が残る。修正後は非ゼロの安全領域を持つ端末で再確認する。

**Finding:** アイコンと文字の左寄りは実測した `MEDIUM / Layout`。4画面に共通するナビの視覚的な対応関係を弱める。タップ不能や横溢れは確認されなかった。安全領域は実機未検証のリスクとして別扱い。

各4分割セルの中央にアイコンと文字が揃った。[修正後320px](ux-after-eval/mobile-nav-after-320-today.png)、[変更前320px](ux-after-eval/mobile-nav-320-today.png) を比較。全3幅で4項目を順にタップし、画面見出しと `aria-current="page"` が各項目に一致した。選択中は上側の線・背景・太字で判別でき、文字やアイコンの欠けは見られない。最小タップ領域は320px時78×48.14px。3幅とも横方向の文書幅は viewport と等しい。

CSS はフッターと本文下余白に `env(safe-area-inset-bottom, 0px)` を使用する。Edge エミュレーションは実際の安全領域を0pxとして返したため、別途24pxの下部余白をスタイル注入で模擬した。その場合フッターは81.14pxに伸び、最下部セレクトとフッターの間に86.25px残り、横溢れなし。[24px 模擬](ux-after-eval/mobile-nav-after-320-safe-area-24-sim.png)。これは CSS 配置の幾何学的確認であり、実際にホームインジケーターを持つ iOS 端末での検証ではない。

**結論:** 指摘された中央揃えは解消。確認した3幅で操作・選択表示・フォーカス表示・最下部到達性に重大な回帰なし。実機の安全領域のみ未検証。
